Engineering choices04 / 05

The main choices, and why I made them.

Flat list, derived tree

A transfer changes one manager ID. Rebuilding avoids keeping a list and nested tree in sync.

Recompute all rollups

The limit is 30 employees. O(n) work is simpler and safer than patching ancestor chains.

Compare real values

I compare before/after rollups. That does not incorrectly mark the shared root as changed.

Keep it local

No database or login. Reset is deterministic; persistence and concurrency are deliberately out of scope.

Trade-off: process-local state, no multi-user isolationBenefit: less code around the core problem
